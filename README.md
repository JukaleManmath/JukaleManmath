## 👨‍💻 About me

I'm a software engineer who likes owning the whole problem, not just one part of the codebase. I've built backend services, web applications, data pipelines, AI workflows, and the infrastructure around them.

My favorite projects are the ones where I can think through the architecture, write the code, put it in production, and learn from what happens next. I care about clean interfaces, sensible tradeoffs, testing, performance, and being able to debug a system when something goes wrong.

Outside of work, you'll usually find me exploring an open source repo, trying a new developer tool, or learning how a system works under the hood.

## 🚀 Selected projects

### [FetchAPI](https://github.com/JukaleManmath/fetchapi) | Making API documentation useful to coding assistants

An open source platform that ingests OpenAPI specifications and gives AI coding assistants grounded knowledge of endpoints, schemas, authentication, and request formats. It combines a web application, API services, hybrid retrieval, and MCP tools to answer questions, validate requests, and help generate integration code.

`Python` `TypeScript` `Next.js` `PostgreSQL` `Qdrant` `Redis` `Docker` `MCP`

### [AgentEval](https://github.com/JukaleManmath/agent-eval-cli) | Testing what AI agents actually do

A CLI for evaluating AI agents through scripted conversations and simulated users. It helps test behavior across multiple turns, inspect results, and catch regressions as agents change.

`Python` `YAML` `LLM Evaluation` `CLI` `CI/CD`

### [MedGuard](https://github.com/JukaleManmath/Medguard-DeID) | Exploring local AI for sensitive text

A proof of concept for detecting and replacing sensitive details in clinical text. It uses local LLM inference and NLP validation to explore safer text processing workflows.

`Python` `Ollama` `spaCy` `NLP` `API Development`

## 💭 How I think about engineering

Good software is more than code that works on your laptop. It needs clear boundaries, useful tests, a deployment path, visibility when things fail, and room to evolve.

I like choosing tools for the problem instead of forcing every problem into the same stack. I also enjoy the less glamorous work: debugging production behavior, reducing complexity, improving documentation, and making life easier for the next developer.
